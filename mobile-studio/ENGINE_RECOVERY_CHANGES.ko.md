# ComfyUI 장애 복구와 서버 실행 상태 표시

- 정상 응답일 때만 재시작을 허용하던 조건을 제거했습니다. 종료·응답 불능 상태에서도 기존 설치의 가상환경 런처와 저장한 실행 인수로 복구합니다.
- 웹앱이 10초 간격으로 확인하고 연속 3회 연결 실패 시 엔진 상태를 검사합니다. 시작 중에는 기다리고, 종료·응답 불능이면 복구를 시도합니다. 실패 시 60초 뒤 재시도합니다.
- 8188 포트의 다른 프로그램과 앱 외부 GPU 작업은 구분합니다. 기존 대상 PID·시작 시각과 GPU 소유권을 다시 확인하며 중복 실행을 막습니다.
- 새 PID의 정상 API 응답과 빈 엔진 큐를 두 번 확인한 뒤, 끊어진 앱 작업을 종료 처리하고 앱 대기 작업을 재개합니다. 저장된 결과와 대기 요청은 보존합니다.
- 웹앱이 재시작되어도 저장된 복구 이벤트의 API 확인을 이어갑니다.
- 네 제어 버튼 각각에 실제 실행 기록과 현재 상태를 표시합니다. 메모리 사용량, 중단 확인 여부, 웹 연결 확인, 엔진 복구 단계·결과·시각을 사용합니다. 고정 안내 문구는 제거했습니다.

## 검증

- 복구/표시/웹 리셋 관련 Node 테스트 14개 통과.
- PowerShell 상태 분류 및 대상 확인 테스트 통과.
- 전체 Node 테스트 실행 당시 87개 통과, 기존 휴지통 테스트 4개는 외부 경로의 임시 디렉터리 생성 권한 때문에 실행 실패했습니다. 이후 추가한 복구 테스트 2개는 별도 통과했습니다.
- 실제 장애 엔진 PID 56040 종료 후 기존 가상환경 런처로 재기동, 새 엔진 PID 68948의 정상 API 응답 검증 완료.
- 복구 이벤트 f69ebe29-0679-474d-92a7-a1e10c92513a 완료 및 기존 대기 작업의 실제 실행 재개 확인.
- 실행 중 웹앱의 상태 API와 브라우저 설정 화면에서 네 상태 영역, 재시작 완료, 엔진 작업 중 상태를 확인했습니다.
- 이전 파일은 backups/engine-recovery-v1 에 보관했습니다.
