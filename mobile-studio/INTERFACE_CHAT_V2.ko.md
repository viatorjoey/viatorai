# 아이콘·영상 재생·채팅 응답 개선

2026-10-16, America/New_York. 기존 웹앱 localhost:8799 및 Tailscale HTTPS에 반영했습니다.

## 화면과 영상

- 완료 카드의 저장·즐겨찾기·재제작·영상 만들기·삭제·복원을 같은 선 두께와 크기의 로컬 SVG 아이콘으로 통일했습니다. 각 버튼은 한국어 접근성 이름과 설명을 유지합니다. 영상 변환은 사진+비디오 카메라, 재제작은 반복 화살표로 구분됩니다.
- 하단 메뉴도 같은 SVG 스타일이며 활성 메뉴는 주황색 배경을 옅게 표시합니다. 생성 방식 카드와 실제 만들기 버튼도 같은 스타일을 사용합니다.
- 영상은 첫 재생 시 **무음·반복 재생·자동 재생**입니다. 이전/다음 버튼이나 슬라이드로 다른 영상으로 이동하면 바로 재생을 시도합니다. 영상 안쪽 우하단에 반투명 스피커·루프 버튼을 배치했습니다. 사용자가 바꾼 설정은 이동 후에도 유지합니다. 브라우저가 소리 있는 자동 재생을 거부하면 무음으로 재시도하고, 재생 자체가 거부되면 안내합니다.
- 채팅 입력 textarea는 **64px → 32px**, 한 줄로 줄였습니다. 첨부·마이크·전송은 같은 30px 버튼과 18px SVG 아이콘입니다. 입력창은 하단 메뉴 위에 유지합니다.

## 채팅 대기 원인과 변경

이전에는 채팅도 n8n의 공용 GPU 잠금과 생성 작업의 순서를 기다리고 ComfyUI 메모리 정리까지 거쳤습니다. 현재 PC는 총 약 64GB RAM이며 점검 시 약 38GB가 비어 있었습니다. 영상 모델과 큰 LLM을 16GB GPU에 함께 올리는 방식 대신, **채팅 전용 CPU Ollama 인스턴스**를 분리했습니다.

- 기존 GPU Ollama(11434), ComfyUI, n8n 설정은 유지했습니다. 같은 설치 바이너리와 기존 모델 파일을 사용하고 모델을 내려받거나 복제하지 않았습니다.
- 채팅용 인스턴스만 **127.0.0.1:11435**에서 실행하며 CUDA/ROCm/Vulkan을 끄고 요청에도 `num_gpu:0`을 지정합니다. 외부에 포트를 열지 않습니다.
- 채팅은 별도 CPU 대기열에서 즉시 처리하므로 영상의 GPU 대기열과 독립적입니다. 한 번에 하나의 채팅 모델만 처리합니다. 아직 제출하지 않은 기존 대기 채팅도 CPU 경로로 전환합니다.
- Qwen은 RAM 9GiB, GPT-OSS는 16GiB를 보수적으로 예상하고, **예상 로드 후 10GiB 이상 여유가 있을 때** 시작합니다. 부족하면 RAM 대기를 표시합니다. 이 값은 실행 전 여유 검사이며 OS 전체의 다른 앱이 쓸 RAM까지 강제로 제한하는 기능은 아닙니다.
- 컨텍스트는 2,048 토큰으로 제한하고 답변을 조각별로 저장·표시합니다. 응답 후 `keep_alive=0`과 명시적 언로드, `/api/ps` 확인으로 모델을 내립니다. 원문 메시지와 5일 보관 정책은 유지합니다. 긴 답변의 토큰 생성 속도는 GPU보다 느릴 수 있습니다.
- CPU 채팅 오류가 이미지/영상 생성이나 VRAM 비우기를 막지 않도록 분리했습니다. 전체 작업중단은 확인 당시의 CPU 채팅과 GPU 작업 모두를 대상으로 하며, 개별 중단은 해당 작업에만 적용됩니다.

CPU 전용 실행 방식은 [Ollama 공식 GPU 선택 문서](https://docs.ollama.com/gpu)의 CPU 강제 사용 설정을 따릅니다.

## 받아쓰기 수정

생성과 채팅이 같은 받아쓰기 모듈을 사용합니다. 매번 새 인식 세션을 만들고, 이전 세션의 늦은 `end` 이벤트가 새 세션을 종료하지 않도록 객체를 확인합니다. `error` 후 `end`가 오지 않아도 상태를 해제하고, `stop` 후 종료가 누락되면 1.2초 안에 복구합니다. 음성 인식이 너무 오래 멈춰 있는 경우와 앱을 백그라운드로 보낸 경우도 정리합니다. 중간 인식 결과를 매번 교체해 같은 문장을 중복해서 붙이지 않습니다. 관련 수명주기는 [SpeechRecognition end 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/end_event)를 기준으로 처리합니다.

## 검증

- 단위·그래프·메모리 정책·음성 세션·재생 상태·기존 기능 테스트 **49개 통과**.
- 격리 API 검증: 채팅/이미지 인증, 중복 제출 방지, 재제작 설정 보존, CPU 오류와 VRAM 비우기 분리, CPU/GPU 전체 중단 및 개별 중단 범위 확인. 사용자 실제 작업을 취소하지 않았습니다.
- 실제 Qwen 텍스트 채팅: 첫 토큰 **6.55초**, 전체 **7.075초**.
- 실제 GPT-OSS 텍스트 채팅: 첫 토큰 **17.966초**, 전체 **18.858초**.
- 실제 Qwen 이미지 첨부 채팅: 첫 토큰 **9.757초**, 전체 **12.486초**.
- 모두 CPU 전용 모델의 `size_vram=0`, 스트리밍 표시, GPU 소유권 없음, 응답 후 빈 모델 목록을 확인했습니다. 짧은 테스트 메시지 결과이며 긴 대화나 시스템 부하에 따라 달라집니다.
- 실제 Z-Image 생성 도중 CPU 채팅을 제출해 **동시 실행**, 채팅 VRAM 0, 답변 저장 및 생성 파일/메모리 정리를 확인했습니다. 생성한 합성 테스트 이미지는 복원 가능한 휴지통으로 옮겼습니다.
- 브라우저: 합성 풍경 영상으로 무음/루프 기본 상태, 스피커·루프 토글, 이전/다음 이동을 확인했습니다. 아이콘·입력창·메뉴는 화면으로 검수했습니다. iPhone 실기기 마이크·자동 재생 정책은 직접 확인이 남습니다.
- 최종 앱/작업자 교체 후 HTTP 200 대기와 기존 HTTPS 인증 확인을 통과했습니다. CPU 포트는 127.0.0.1 바인딩을 확인했습니다.

실측 파일: `data/chat-fast-live-results.json`, `data/chat-cpu-vision-results.json`, `data/chat-concurrent-results.json`. 변경 전 소스 사본은 `data/before-icons-cpu-chat/`입니다. `sources/`는 수정하지 않았습니다.
