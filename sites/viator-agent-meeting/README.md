# 비아토르 AI 디렉팅룸

## 로그인 커넥터: 클로드와 그록

회의실은 `/mcp/claude`와 `/mcp/grok`에 에이전트별 원격 MCP 도구를 제공합니다. Claude Pro와 Grok Pro 사용자는 각 서비스의 사용자 지정 커넥터 화면에서 해당 주소를 추가하고, 이 비공개 Site를 쓰는 계정으로 로그인해 승인합니다. 회의 참여 커넥터 자체는 별도 Anthropic/xAI API 키를 사용하지 않습니다. 그록 Imagine 영상의 실제 실행은 선택 사항인 서버용 xAI API 키가 연결된 경우에만 가능합니다.

두 커넥터의 권한은 프로젝트별 회의 읽기, 공유 기억 읽기, 자기 이름으로 답장하기로 제한됩니다. 공개 게시, 삭제, 결제, Windows 명령 실행 권한은 제공하지 않습니다. 파일 수정과 명령 실행이 필요하면 Claude Desktop/Code 또는 Grok의 공식 로컬 작업 기능에서 사용자가 허용한 폴더와 도구만 쓰고, 결과를 `meeting_reply`로 회의실에 보고합니다. 로그인 커넥터는 각 AI 앱이 도구를 호출할 때 작동하므로 서버가 소비자용 Pro 세션을 임의로 깨우거나 자동 조작하지 않습니다.

공통 생성 도구는 지피·재미니·클로드·그록·뮤즈가 모두 `generation_capabilities`로 모델을 확인하고 `generation_propose`로 이미지·영상 제작안을 등록할 수 있게 합니다. 제작안은 항상 `awaiting_approval`로 저장되며 이 도구만으로 크레딧을 쓰거나 생성·게시할 수 없습니다. 치프가 회의실에서 승인한 뒤에만 OpenAI 이미지, 재미니 Nano Banana 2/Pro, Higgsfield Seedance·Kling·Wan, Windows ComfyUI 중 선택한 엔진이 실행됩니다. 완성 결과는 다시 회의실에 표시되어 승인, 수정 요청 또는 삭제를 거칩니다.

영상 제작은 글로 영상 만들기와 사진을 영상으로 만들기를 구분합니다. 기준 사진은 비공개 저장소에 보관되고, 승인된 작업에서만 재미니 Veo 3.1, 그록 Imagine 1.5, Higgsfield Seedance·Kling·Wan 또는 Windows ComfyUI로 전달됩니다. 모델별 추천 용도와 연결 상태를 공통 capability 목록으로 제공하므로 모든 에이전트가 같은 선택지를 사용합니다.

치프, 지피(OpenAI Director), Muse, 재미니(Gemini)가 한 대화방의 원문과 누적 기억을 공유합니다. 화면은 1초마다 새 발언을 확인합니다. 재미니(Gemini)는 서버 전용 `GEMINI_API_KEY`로 Google의 Gemini API를 직접 호출합니다. 치프 또는 Muse의 새 발언 뒤 지피 → 재미니(Gemini) → 지피 순서로 한 번 이어지고, 이후에는 다음 치프 또는 Muse 발언을 기다립니다. 총 대화 횟수에는 앱의 고정 상한이 없으며 중지 버튼으로 언제든 멈출 수 있습니다. 지피는 Muse나 재미니(Gemini)를 대신해 말하지 않도록 제한합니다.

새 회의를 만들 때는 이름만 저장하며 에이전트 발언이나 모델 호출을 만들지 않습니다. 치프가 그 회의에 첫 지시를 보낸 뒤 지피(OpenAI Director), 재미니(Gemini), Muse의 참여 흐름이 시작됩니다. 회의 이름은 대화와 제작 기록을 유지한 채 언제든 수정할 수 있습니다. 텍스트 답장에는 앱의 별도 승인 단계가 없으며 Muse 자체 정책과 지원 기능은 우회하지 않습니다. API 잔액 또는 공급자 사용 한도에 도달하면 needs_review로 멈추며 자동 충전하거나 반복 호출하지 않습니다.

한 회차에서 지피·재미니·Muse가 모두 실제로 발언하면 지피가 회의 결론을 한 번 작성합니다. 실행할 일이 여러 개면 서로 독립된 실행 항목으로 나누며, 치프는 각 항목을 따로 승인하거나 반려합니다. 이미지·영상 항목은 승인과 동시에 선택된 제작 엔진으로 전달되고, 아직 자동 실행기가 없는 항목은 담당자에게 배정된 상태로 기록됩니다.

## 현재 상태

- 비공개 Sites 클라우드 앱. ChatGPT 로그인으로 치프만 화면에 접근합니다.
- D1에 프로젝트별 대화·수신 임대·중복 방지·응답 이력·audit를 저장합니다.
- 서버 전용 OPENAI_API_KEY, GEMINI_API_KEY와 모델 설정은 Sites runtime secrets에서 관리합니다. 키는 소스/브라우저 코드에 없습니다.
- Muse는 아직 연결되지 않았습니다. UI의 Muse 연결에서 전용 비밀 파일을 받아 Muse 비밀 저장소에 전달하고, 키가 없는 연결 요청 문구를 한 번 전달해야 합니다. 실제 Muse 실행 로그와 첫 HTTP 요청이 확인돼야 연결 완료입니다.
- 치프Mechanic 조직의 키로 실제 OpenAI HTTP 200 응답 및 클라우드 지피 첫 메시지를 확인했습니다. 초기 오류는 Personal 조직 키와 치프Mechanic 잔액의 조직 불일치였으며 추가 충전하지 않았습니다.
- 자동 응답 로직 테스트는 mock 모델·mock HTTP 어댑터를 사용합니다. 실제 Muse 대화나 실제 모델 성공이라고 해석하면 안 됩니다.

## 사용법

1. 클라우드 사이트에 치프의 ChatGPT 계정으로 로그인합니다.
2. 통신 테스트 프로젝트에서 Muse 연결 → 비공개 연결 파일 받기를 선택합니다. 파일에는 비밀 인증이 있어 공개하거나 채팅에 내용을 붙이면 안 됩니다.
3. 다운로드한 파일을 Muse 대화에 실제 첨부하고 연결 요청 복사 문구를 보냅니다. UI에서 파일을 받았다는 것은 Muse에 전달했다는 뜻이 아닙니다. Muse는 회의 메시지와 공개 게시 작업을 구분합니다. 공개 게시 작업은 치프가 완성 결과 화면에서 직접 승인한 경우에만 15초 간격으로 가져옵니다.
4. 주제를 입력하고 대화 시작을 누릅니다. 치프가 같은 방에 메시지를 보내거나 Muse의 실제 답장이 POST되면 지피가 자동 응답합니다.
5. 멈춤을 누르면 대화를 중지하고 기존 수신 임대를 무효화합니다.

지피는 이 Codex/ChatGPT 채팅 세션과 별개인 API 워커입니다. 이 창의 모델이 자동으로 깨어나는 기능이 아닙니다. UI에 실제 Muse 대신 OpenAI로 연기하는 봇을 넣지 않았습니다.

## Muse HTTP 계약

프로젝트별 연결 파일의 origin/headers를 사용합니다. Owner-private Sites의 서비스 인증과 Muse 프로젝트 토큰이 모두 필요합니다. 서비스 인증만으로 치프의 관리 API를 사용할 수 없습니다. 추가 Muse 토큰은 D1에 해시만 저장합니다. 파일 재발급 시 해당 프로젝트의 이전 Muse 토큰을 폐기합니다.

- GET /api/muse/info: 계약 확인
- POST /api/muse/heartbeat: 접속 확인
- POST /api/muse/pull: {projectId}; 임대된 delivery/message/room 또는 delivery:null
- POST /api/muse/reply: {deliveryId,leaseId,reply}; Idempotency-Key 필수

임대는 10분이며 최대 수신 시도 5회입니다. 만료 후 backoff를 거쳐 재수신합니다. 같은 답장을 재시도할 때 원래 메시지 ID에 고정된 키와 처음 답장 본문을 유지하세요. 게시나 명령 실행은 프로토콜에 없습니다. HTTP 요청 크기·메시지 길이를 제한합니다. OnlyFive/MOSO/통신 테스트 토큰과 대화는 분리합니다. 기존 Windows 제작 데이터는 가져오지 않았습니다.

연결 상태 online은 최근 3분 내 해당 자격 증명으로 HTTP 요청을 받았다는 뜻이며, 요청 주체가 실제 Muse 모델인지는 해당 Muse 실행 로그와 함께 확인해야 합니다.

Worker 프로세스 중단 시 진행 중 요청의 수동 확인이 필요할 수 있습니다.

## 치프 대화 참여

새 주제에서는 먼저 회의 이름만 정합니다. 생성 직후에는 모든 에이전트가 조용히 대기하고, 치프가 첫 지시를 보내면 같은 회의 안에서 지피·재미니·Muse가 참여합니다. 대화 중 주제가 바뀐 최신 발언을 우선하도록 이전 Muse 수신 임대는 취소됩니다. 답변 생성 중에는 다음 발언을 작성할 수 있으나 생성이 끝나야 전송할 수 있습니다. 멈춘 회의는 치프가 새 메시지를 보내면 다시 시작합니다. 새 주제 버튼으로 다른 회의를 만들고, 이름 수정 버튼으로 기존 기록을 보존한 채 회의 이름을 바꿀 수 있습니다.

## 입력과 삭제

Enter는 전송, Shift+Enter는 줄바꿈입니다. 한글 등 IME 조합 중 Enter와 길게 누른 반복 입력은 전송하지 않습니다. 대화 삭제는 해당 방을 휴지통으로 옮기고 수신 대기를 취소합니다. 메시지는 보관해 복원할 수 있으며, 복원된 대화는 멈춘 상태로 열립니다. 삭제 당시 이미 시작한 API 요청은 끝날 수 있지만 삭제 상태를 해제하거나 Muse에게 새 메시지를 보내지 않습니다.

## 응답 미완료 복구

한 응답의 생성 여유는 4096 토큰이며 gpt-5.4-mini의 reasoning effort를 none으로 명시합니다. 답변은 핵심 위주 2000자 이내로 요청합니다. 이는 대화 횟수 제한이 아닙니다. incomplete 응답은 원인 코드를 audit에 기록하고 본문을 전달하지 않습니다. needs_review 상태에서 응답 다시 받기를 누르면 최신 실패 메시지에 대한 응답만 새로 생성합니다. 원문 메시지를 중복 추가하지 않고 요청 키와 원자적 재개 권한으로 중복 호출을 막습니다. 자동으로 반복 재시도하지 않습니다.

## 세 사람의 대화 기억

대화 원문은 계속 보관하며 방마다 hub_room_memory에 누적 요약을 저장합니다. 지피는 기존 요약·아직 요약하지 않은 발언·최근 12개 원문을 함께 읽습니다. 같은 응답 요청에서 message와 memory를 받아 별도 요약 API 호출 없이 함께 저장합니다. 요약에 들어갈 과거 기록은 한 번에 48,000자 이내의 온전한 메시지 묶음으로 순서대로 처리하며, 긴 기존 대화는 여러 응답에 걸쳐 반영됩니다. 전체 대화 저장 개수를 제한하지 않습니다.

기억 버튼은 저장된 요약과 갱신 시각을 보여줍니다. 요약에는 치프가 밝힌 사실·결정·참여자별 제안·미결정 사항을 구분하도록 요청하며 최신 정정을 우선합니다. AI 요약은 세부 정보를 생략하거나 오류가 있을 수 있어 원문이 최종 근거입니다. 기록은 다른 방이나 프로젝트로 자동 전파하지 않습니다. 삭제된 방의 기억은 숨기고 복원할 때 다시 함께 사용할 수 있습니다.

Muse pull 응답의 context.memory와 context.recentMessages에 같은 기억과 최근 대화를 제공합니다. GET /api/muse/memory?roomId=...도 프로젝트별 Muse 토큰으로 읽을 수 있습니다. 이 API는 Muse 자체 장기 기억이나 예약 실행을 자동 설정하지 않습니다. 현재 Codex/ChatGPT 채팅이 클라우드 대화를 자동으로 읽거나 영구적으로 학습한다는 의미도 아닙니다.

## 프로젝트 전체 기억

프로젝트 기억은 방별 자동 요약과 별도로 `hub_project_memory`에 저장합니다. 과거 ChatGPT/Codex 작업에서 확정된 환경, 결정, 완료 상태와 미해결 작업을 비밀값 없이 정리해 넣을 수 있습니다. 같은 프로젝트의 지피·재미니·Muse는 다음 발언부터 이 공통 배경을 받습니다. 통신 테스트, MOSO, OnlyFive의 기억은 프로젝트 키로 분리됩니다.

Sites 서버가 ChatGPT 계정의 과거 대화를 임의로 읽는 상시 권한은 없습니다. 현재 가져오기는 치프 계정으로 확인한 프로젝트 기록을 요약해 소유자 전용 화면/API로 저장하는 방식입니다. 원문 전체나 인증 키를 복제하지 않으며, 프로젝트 기억 화면에서 내용을 검토하고 고칠 수 있습니다.

## 제작 실행 브리지

회의실의 대화에서 실행 가능한 이미지·영상 기획이 완성되면 제작안이 자동으로 `awaiting_approval` 상태에 저장됩니다. **제작안** 버튼으로 직접 만들 수도 있습니다. 치프가 대화로 “응 진행해”라고 답하거나 **승인하고 실행**을 누른 작업만 프로젝트별 스튜디오 큐에 들어갑니다. Windows 제작 PC에서 `studio-bridge.mjs`, `start-studio-bridge.cmd`, 프로젝트별 `viator-studio-<project>.private.json`을 같은 폴더에 두고 시작 파일을 실행하면 승인된 작업을 기존 스튜디오 API에 중복 방지 요청 번호와 함께 제출합니다. 완성 파일은 비공개 클라우드 저장소에 복사되어 같은 회의에 표시됩니다. 치프는 결과를 수정하거나 거절해 삭제할 수 있습니다. **승인하고 Threads 게시**를 누른 결과만 고정된 치프 Threads 계정의 Muse 게시 대기열에 한 번 들어가며, 일반 회의 메시지는 공개 게시 권한으로 취급하지 않습니다.
